Пополнение BoostUp
подарками через Crafter.

Игрок отправляет подарок на релейер Crafter. Бот спрашивает, куда его отправить. Если игрок выбирает BoostUp и подтверждает передачу, этот же подарок сразу передаётся в инвентарь аккаунта BoostUp внутри Crafter ({{ account }}). Crafter присылает BoostUp подписанный webhook, и BoostUp добавляет этот NFT в инвентарь игрока.

Подарок, а не деньги. На баланс BoostUp ничего не зачисляется. BoostUp получает сам NFT; цена (в TON и GRAM, по флору коллекции) приходит только для информации, игрок видит её в окне подтверждения в GRAM.

01Как это работает

  1. Игрок отправляет подарок на релейер Crafter. Он должен хотя бы раз открыть приложение Crafter: так Crafter узнаёт, чей это подарок.
  2. Бот Crafter пишет игроку: «Куда отправить подарок?» с двумя кнопками: «В маркет» (подарок остаётся в инвентаре Crafter) и «В BoostUp».
  3. «В BoostUp» → подтверждение. Бот просит подтвердить и даёт кнопку, которая открывает окно Crafter: большая анимация подарка, название и цена в GRAM. Кнопка «Подтвердить» открывает второе окно «Точно передать подарок в BoostUp?», и только «Да, передать» запускает передачу.
  4. Подарок передаётся внутри Crafter. В одной операции он исчезает из инвентаря игрока и появляется в инвентаре аккаунта BoostUp ({{ account }}). Через Telegram ничего не отправляется: передача мгновенная, без комиссии и без ожидания.
  5. Webhook в BoostUp. Crafter отправляет deposit.delivered с данными игрока и подарка. BoostUp добавляет NFT в инвентарь игрока и отвечает {"ok": true}.
  6. Игроку приходит сообщение бота: подарок зачислен в инвентарь BoostUp.
Игрок один и тот же. Игрок определяется по Telegram ID: поле telegram_id в webhook совпадает с Telegram ID игрока в BoostUp.

02Два ключа

КлючКто получаетДля чего
1. Ключ Partner API CRT/…Все, через бота командой /api. У аккаунта BoostUp тоже есть такой.Обычная работа с аккаунтом Crafter через API: посмотреть полученный подарок, продать, передать, вывести в Telegram. Описание: /partner-api.
2. Личный ключ BoostUp BUP/…Только BoostUp, лично от Crafter.Подключение именно пополнения: список пополнений, подтверждение зачисления. Только для сервера BoostUp.
Ключи нельзя показывать. Храните их на сервере в переменных окружения, не в репозитории, логах и клиентском коде. Запросы с заголовком Origin (из браузера) отклоняются. Если ключ мог утечь, попросите Crafter заменить его: старый перестанет работать сразу. Ключ BUP/… не открывает Partner API, а ключ CRT/… не открывает API пополнения.

Что должен ответить BoostUp

ОтветЧто делает Crafter
HTTP 2xx и {"ok": true}Считает подарок зачисленным, пишет игроку «подарок в инвентаре BoostUp». Можно добавить "external_id" — ваш номер операции.
Любой другой ответ, таймаут, ошибка сетиПовторяет webhook: через 10 сек, 30 сек, 2 мин, 10 мин, 30 мин, затем каждый час, пока не получит ответ.
Зачисляйте идемпотентно. Один и тот же deposit_id может прийти несколько раз (повтор после сбоя). Если пополнение с таким deposit_id уже зачислено, не зачисляйте второй раз и ответьте {"ok": true}.
  • Проверяйте подпись до любых действий. Для подписи используйте исходные байты тела, не пересобранный JSON.
  • Отклоняйте запросы со старым X-Crafter-Timestamp (старше 5 минут): так не получится повторить чужой запрос.
  • Отвечайте за 8 секунд: дольше Crafter не ждёт и повторит запрос.

05Проверка подписи

# Python (Flask)
import hashlib, hmac, time

SECRET = "секрет_подписи_из_админки"

def verify(raw_body: bytes, headers) -> bool:
    stamp = headers.get("X-Crafter-Timestamp", "")
    if not stamp.isdigit() or abs(time.time() - int(stamp)) > 300:
        return False
    expected = hmac.new(SECRET.encode(), stamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest("sha256=" + expected, headers.get("X-Crafter-Signature", ""))
// Node.js (Express: тело как Buffer, express.raw({type: "application/json"}))
const crypto = require("crypto");
function verify(raw, headers) {
  const stamp = headers["x-crafter-timestamp"] || "";
  if (!/^\d+$/.test(stamp) || Math.abs(Date.now() / 1000 - Number(stamp)) > 300) return false;
  const expected = "sha256=" + crypto.createHmac("sha256", process.env.CRAFTER_SECRET)
    .update(Buffer.concat([Buffer.from(stamp + "."), raw])).digest("hex");
  const given = headers["x-crafter-signature"] || "";
  return given.length === expected.length && crypto.timingSafeEqual(Buffer.from(given), Buffer.from(expected));
}

06API пополнения

Эти запросы нужны, чтобы сверить пополнение и подтвердить зачисление, если webhook не дошёл. Авторизация: Authorization: Bearer BUP/ваш_ключ. Только с сервера, не из браузера. Лимит: {{ limit }} запросов за {{ window }} секунд, при превышении 429 и Retry-After. Ответы всегда JSON, ошибка выглядит так: {"ok": false, "error": "текст", "code": "код"}.

ЗапросЧто делает
GET /pingПроверка ключа: включена ли интеграция, задан ли webhook, аккаунт BoostUp в Crafter.
GET /depositsСписок пополнений, новые первыми. Параметры: status, limit (1–100, по умолчанию 50), after (время создания, секунды).
GET /deposits/{deposit_id}Одно пополнение: игрок, подарок, цена, статус.
POST /deposits/{deposit_id}/ackПодтвердить зачисление: {"external_id": "ваш_номер"} (необязательно). Повтор безопасен.
curl {{ base }}/deposits?status=delivered \
  -H "Authorization: Bearer BUP/ваш_ключ"
Если webhook не доходит. Раз в несколько минут запрашивайте GET /deposits?status=delivered, зачисляйте найденное (идемпотентно по deposit_id) и вызывайте /ack. Подарок при этом уже лежит в инвентаре аккаунта BoostUp.

07Работа с подарком после зачисления

Подарок лежит в обычном инвентаре аккаунта BoostUp в Crafter. Дальше с ним работают обычным ключом Partner API (Authorization: Bearer CRT/…, адрес {{ partner_base }}):

ЗадачаЗапрос
Найти подарокGET /inventory или GET /gifts/{gift_id}, где gift_id из webhook
Вывести в TelegramPOST /withdraw (комиссия вывода 0,4 GRAM с баланса аккаунта)
Передать игроку CrafterPOST /transfer, в том числе с "pay_withdraw_fee": true
Выставить на продажуPOST /sell

Все запросы записи требуют Idempotency-Key. Подробности и примеры: /partner-api.

  • Не выставляйте и не выводите подарок, пока не зачислили его игроку.

11Проверка до запуска

  1. Ключ. GET {{ base }}/ping возвращает "ok": true и аккаунт BoostUp.
  2. Webhook. Администратор Crafter нажимает «Отправить тестовый webhook» в разделе «BoostUp». К вам приходит событие ping: проверьте подпись и ответьте 2xx.
  3. Настоящее пополнение. Отправьте недорогой подарок на релейер Crafter с аккаунта, у которого есть и Crafter, и BoostUp. Пройдите кнопки бота и оба окна подтверждения. Убедитесь, что подарок появился в инвентаре аккаунта BoostUp (GET /inventory с ключом CRT/…) и NFT добавлен игроку в BoostUp.
  4. Повтор. Проверьте, что повторный deposit_id не зачисляется второй раз.

12Перед запуском

  • Подпись webhook проверяется, старые запросы отклоняются.
  • Зачисление идемпотентно по deposit_id.
  • Адрес webhook отвечает быстрее 8 секунд.
  • Раз в несколько минут BoostUp сверяет GET /deposits?status=delivered.
  • Оба ключа и секрет лежат только на сервере.
  • Аккаунт BoostUp в Crafter открывал приложение и имеет ключ CRT/….
